# session_vlan — модуль сессий и VLAN для BRAS-прототипа

Учебный модуль из проекта `godummy`, демонстрирующий:
- работу с **sentinel-ошибками** (`ErrInvalidVLAN`);
- паттерн **обёртывания ошибок** через `%w`;
- разделение **бизнес-логики** и **политики обработки ошибок**;
- контракт функции: при ошибке всегда возвращается `nil` сессия.

## Назначение

Модуль отвечает за создание сессии абонента и валидацию VLAN в соответствии со стандартом IEEE 802.1Q (1–4094). Используется как основа для интеграции с биллингом и Accel-PPP в проекте `sun-bng`.

## Основные сущности

- `Session` — структура сессии абонента.
  - `ID` — идентификатор пользователя от биллинга.
  - `vlan` — внутренний VLAN абонента (приватное поле).
- `ErrInvalidVLAN` — sentinel-ошибка для идентификации невалидного VLAN (мусорные данные от биллинга).
- `HandleAuth(userID, rawVlan)` — публичная функция создания сессии.
  - **Не печатает в консоль.**
  - Возвращает `(nil, err)` при ошибке — вызывающий сам решает, WARN это или PANIC.
  - Гарантирует инвариант: при ошибке состояние сессии не меняется.
- `SetVLAN(vlan)` — сеттер VLAN с валидацией диапазона.

## Контракт API

| Функция | Возвращает при успехе | Возвращает при ошибке |
| --- | --- | --- |
| `HandleAuth` | `(*Session, nil)` | `(nil, ErrInvalidVLAN)` |
| `SetVLAN` | `nil` | `ErrInvalidVLAN` (обёрнутая) |

**Важно:** никогда не вызывайте `sess.VLAN()` без проверки `err != nil`. При ошибке `sess` гарантированно `nil`.

## Как запустить

### Демо-запуск

```bash
cd ~/projects/godummy/02-errors/session_vlan
go run .
```
Ожидаемый вывод:

```text
OK: Сессия создана, VLAN = 100
WARN: Пользователь user-bad — недопустимый VLAN: vlan=9999: invalid VLAN. Требуется проверка.
```
### Тесты
```bash 
go test -v ./...
```
### Тесты покрывают:
- граничные значения VLAN (1, 4094, 4095);
- отрицательные и нулевые значения;
- проверку, что при ошибке сессия остаётся nil;
- проверку сохранения старого VLAN при неудачном сетте.

### Архитектурные решения и инсайты
1. Разделение ответственности. Логика валидации VLAN находится в SetVLAN, а решение «WARN или PANIC» вынесено в main.go. Это позволяет использовать HandleAuth в разных контекстах (HTTP-хендлер, worker, CLI) без дублирования логики.
2. Sentinel-ошибки. ErrInvalidVLAN используется для точного распознавания мусорных данных от биллинга через errors.Is(err, ErrInvalidVLAN). Это предпочтительнее строковых сравнений.
3. Отсутствие побочных эффектов. Функция HandleAuth ничего не печатает и не отправляет в мониторинг. Такой подход делает её легко тестируемой и пригодной для использования в агентах и библиотеках.
4. Инвариант состояния. Сеттер SetVLAN не изменяет состояние объекта при ошибке. Тест TestSetVLANKeepsOldValueOnFailure гарантирует соблюдение этого правила.

## План миграции в sun-bng

При переносе в основной проект:
1. Переименовать пакет main → package session в папке internal/session.
2. Убедиться, что HandleAuth остаётся публичным (с большой буквы).
3. Заменить fmt.Printf в main на вызовы логгера (logger.Warn) и, при необходимости, запись в PostgreSQL.
4. Добавить обработку дополнительных полей биллинга (скорость, профиль, IP-пул).

Примеры использования:
``` go
sess, err := HandleAuth("user-123", 100)
if err != nil {
    if errors.Is(err, ErrInvalidVLAN) {
        logger.Warn("invalid_vlan", "user", "user-123")
        return
    }
    logger.Error("unexpected_error", "err", err)
    return
}

// Здесь можно передать sess в Accel-PPP или сохранить в NetBox

```
