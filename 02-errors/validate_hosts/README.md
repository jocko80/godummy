# validate_hosts — модуль строгой валидации IP-адресов

Учебный модуль из проекта `godummy`, демонстрирующий:
- работу с пакетом `net/netip` (Go 1.18+): быстрый, безопасный, значение вместо указателя;
- sentinel-ошибки (`ErrEmptyIP`, `ErrInvalidIP`) и обёртывание через `%w`;
- паттерн «единая точка парсинга» (`Parse`) и удобные обёртки (`Validate` — DRY);
- строгие политики: как отличить чистый IPv4/IPv6 от гибридного IPv4-mapped.

Используется как основа валидации адресов для биллинга, NetBox и Accel-PPP в проекте `sun-bng`.

## Назначение

Модуль отвечает за синтаксический разбор и строгую проверку IP-адресов,
поступающих из биллинга и API. Результат используется для:
- принятия решения о создании сессии;
- передачи корректных адресов в Accel-PPP (IPoE);
- создания IP-адресов в NetBox.

## Основные сущности

- `ErrEmptyIP` — sentinel-ошибка: пустая строка вместо адреса.
- `ErrInvalidIP` — sentinel-ошибка: неверный формат или нарушение строгой политики.
- `Host` — структура-владелец адреса (`Host{IP: "..."}`), все методы — на ней.
- `Parse()` — **единая точка истины** для разбора: сначала проверка на пустоту,
  потом `netip.ParseAddr`. Все остальные методы идут через неё.
- `Validate()` — удобная обёртка: возвращает только факт валидности (ошибку), без адреса.
- `ParseStrictIPv4()` — принимает ТОЛЬКО чистый IPv4. Отвергает IPv6 и гибриды `::ffff:192.168.1.1`.
- `ParseStrictIPv6()` — принимает ТОЛЬКО чистый IPv6. Отвергает IPv4 и гибриды `::ffff:192.168.1.1`.

## Контракт API

| Функция | При успехе | При ошибке |
| --- | --- | --- |
| `Host.Parse()` | `(netip.Addr, nil)` | `(netip.Addr{}, ErrEmptyIP / ErrInvalidIP)` |
| `Host.Validate()` | `nil` | ошибка от `Parse` (без адреса) |
| `Host.ParseStrictIPv4()` | `(netip.Addr, nil)` | `(netip.Addr{}, ErrInvalidIP)` |
| `Host.ParseStrictIPv6()` | `(netip.Addr, nil)` | `(netip.Addr{}, ErrInvalidIP)` |

**Важно:** функции ничего не печатают в консоль. Все решения о WARN/ERROR принимает вызывающий
(в демо — `main.go`, в проде — контроллер с логгером). Ошибки всегда обёрнуты с контекстом
(`address %q: %w`), чтобы в логах было видно, какая именно строка не прошла.

## Ключевой инсайт: ловушка IPv4-mapped

Синтаксис `::ffff:192.168.1.1` — это **легальный IPv6-адрес**, в который «завёрнут» IPv4.
Проблема в том, что:

- `addr.Is6()` вернёт `true` и для чистого IPv6, и для гибрида — она **лжёт** на `::ffff:x.x.x.x`;
- единственный надёжный способ отсечь гибрид — проверка `addr.Is4In6()`.

Именно поэтому в `ParseStrictIPv6` условие составное:

```go
if !addr.Is6() || addr.Is4In6() {
    return netip.Addr{}, fmt.Errorf("address %q: %w (требуется чистый IPv6)", h.IP, ErrInvalidIP)
}
```
Зачем это нужно: в строгих сетевых политиках гибрид часто означает «грязные данные от биллинга» — один и тот же хост приходит то как IPv4, то как IPv4-in-IPv6, и это ломает ACL и пулы адресов.

```
Ожидаемый вывод:

  -> Strict IPv4: ОТКЛОНЕН
  -> Strict IPv6: ОТКЛОНЕН

Тест: Невалидный синтаксис ("999.0.0.1")
  -> Strict IPv4: ОТКЛОНЕН
  -> Strict IPv6: ОТКЛОНЕН

Тест: Пустая строка ("")
  -> Strict IPv4: ОТКЛОНЕН
  -> Strict IPv6: ОТКЛОНЕН
```
Тесты
```bash
go test -v ./...
```
Тесты покрывают:
- валидный IPv4 и IPv6 (приняты соответствующим строгим парсером, отклонены другим);
- IPv4-mapped (::ffff:192.168.1.1) — отвергнут обоими строгими парсерами;
- невалидный синтаксис (999.0.0.1) — sentinel ErrInvalidIP;
- пустую строку — sentinel ErrEmptyIP;
- контракт: при ошибке адрес нулевой (netip.Addr{}), не «мусорный».

## Архитектурные решения и инсайты
1. Единая точка парсинга. Все проверки начинаются с Parse(). Строгие парсеры не дублируют netip.ParseAddr, а вызывают общий метод — так политика валидации живёт в одном месте.
2. DRY через Validate(). Когда нужен только факт валидности, не тяну весь адрес — обёртка переиспользует Parse() без нового кода.
3. netip.Addr вместо net.IP. Это значение (не указатель): нельзя вернуть nil, легко сравнивать через ==, нет скрытого состояния «4-байтовый или 16-байтовый слайс». Ошибка всегда сопровождается нулевым netip.Addr{} — контракт однообразен.
4. Sentinel-ошибки + обёртка. errors.Is распознаёт причину отказа, а %q в сообщении сохраняет исходную строку — для отладки грязных данных из биллинга.
5. Отсутствие побочных эффектов. Модуль не печатает, не пишет в БД, не ходит в сеть.

## План миграции в sun-bng
При переносе в основной проект:
1. Переименовать пакет main → package host в папке internal/host.
2. Убедиться, что Parse и строгие парсеры остаются публичными (методы с большой буквы уже публичны).
3. Заменить fmt.Printf в main.go на вызовы логгера (logger.Warn).
4. Добавить следующий уровень политики: IsAllowedIP — проверка попадания в пулы адресов из NetBox/PostgreSQL (отдельный модуль, не тот же файл).
5. При необходимости добавить ValidateHost(host string) для DNS-имён с таймаутами и кэшем.

Пример использования в коде
```go
h := Host{IP: rawIPFromBilling}
addr, err := h.ParseStrictIPv4()
if err != nil {
    if errors.Is(err, ErrInvalidIP) {
        logger.Warn("not_pure_ipv4", "raw", rawIPFromBilling)
        return
    }
    if errors.Is(err, ErrEmptyIP) {
        logger.Warn("empty_ip", "user", userID)
        return
    }
    logger.Error("unexpected_error", "err", err)
    return
}
// addr готов: передаём в Accel-PPP или сериализуем в NetBox
```
